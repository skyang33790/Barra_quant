# 横截面多因子策略框架 V1 设计

日期：2026-09-11  
状态：已完成 brainstorming 与 grilling，待实施计划  
适用项目：`E:\0KD\Barra_quant`

## 1. 最终判决

V1 必须拆成两个清晰阶段：

- **V1a 工程验收**：使用现有短样本验证数据契约、时间对齐、因子计算、账户会计、
  A 股交易状态和可重现性。所有结果强制标记为 `SMOKE_TEST`。
- **V1b 研究验证**：只有接入满足本设计数据资格门的多年数据后，才允许评价因子稳定性、
  统计显著性和可投资性。

V1a 的完成与收益、IC、Sharpe 正负完全脱钩。当前数据不得支持任何“因子有效”结论。

## 2. V1a 目标和非目标

### 2.1 V1a 目标

1. 从现有 DuckDB 读取标准化日频 OHLCV。
2. 构建明确标记为不完整的历史时点近似股票池。
3. 计算三个固定价量因子、开盘到开盘标签和研究诊断。
4. 完成价格型 `Barra-lite` 风格审计。
5. 生成 Top 50 只做多目标组合。
6. 用单策略、单人民币账户的有状态执行器验证 A 股成交约束。
7. 输出可重放、可审计、内容寻址的运行产物。

### 2.2 明确不进入 V1a

- 新正式数据源的接入实现。
- 因子窗口调参、因子筛选或权重优化。
- 机器学习训练、特征流水线、Walk-Forward 或模型接口预留。
- 完整 Barra 风险模型及行业、市值、价值、盈利、成长、杠杆暴露。
- Broker、PaperBroker、RealBroker 或实时行情连接。
- 多策略、多账户、共享持仓或资金分配。
- 实时调度、交互式 Dashboard 和实盘接口。
- 任何因子有效性或可投资性结论。

## 3. 当前数据的身份

现有链路为：

```text
guidebee/china-stock-data
  -> raw Git 数据快照
  -> normalized Parquet
  -> DuckDB
```

当前价格数据覆盖 2026-02-10 至 2026-06-05，共 73 个交易日、399,984 行。
它只作为 V1a 的开发夹具，不能作为正式研究源，原因包括：

- 历史长度不足。
- 未提供可靠的复权与公司行为事件。
- 缺少历史 ST、上市、退市、停牌和上市初期状态。
- `company_snapshot_current` 是当前快照，不是 PIT 证券主表。
- 上游仓库未发现明确的许可证文件。

原始数据仅限本地开发验证，不随项目再分发。正式使用前必须确认授权。

## 4. 数据快照与可重现性

raw 层不得被 `git pull` 原地覆盖。每次获取都写入以源提交号命名的不可变目录：

```text
data/raw/china-stock-data/<source_commit>/
  data/...
  manifest.json
```

`manifest.json` 至少保存：

- 源 URL、提交号、提交时间和抓取时间。
- 每个原始文件的相对路径、字节数和 SHA-256。
- schema 版本和抓取程序版本。

相同提交目录存在时必须校验哈希，不得覆盖。规范化数据和策略运行都必须引用具体
`source_commit`。只保存提交字符串而不保留对应原始内容，不视为可重现。

## 5. V1b 数据资格门

正式研究数据至少包含：

1. 不少于 5 年的原始日线行情。
2. 独立官方交易日历。
3. 逐次公司行为事件及其发布时间、生效日和参数。
4. 带生效区间的 PIT 证券主表。
5. 历史上市、退市、ST/*ST、停牌、板块和交易约束状态。
6. 退市、收购、私有化等终值事件。

每类数据至少包含：

- `event_date`：经济或市场事件所属日期。
- `available_at`：策略最早可以看到该记录的时间。
- `ingested_at`：本地获取时间。
- `source_version`：可复现的来源版本。

所有策略查询必须满足 `available_at <= decision_time`。

新数据源成为正式研究源前，必须按市场、年份和公司行为类型抽样，与独立来源核对
OHLCV、复权、证券状态和公司行为。差异必须解释并记录，不能静默选择一个值。

## 6. 交易日历与时间语义

### 6.1 日历

- V1a 可从全市场不同 `trade_date` 生成近似日历，但必须标记
  `calendar_source = inferred_from_prices`。
- V1b 必须使用独立官方日历。官方应开市但全市场无数据时立即失败，不能误判为休市。
- 日期偏移按市场日历，不能按单只股票下一次有报价的日期跳过停牌期。

### 6.2 信号、成交和标签

- 因子数据截止：`T` 日收盘。
- 信号生成：`T` 日收盘后。
- 周度信号日：每个自然周最后一个市场交易日。
- 计划成交：市场下一交易日 `T+1` 开盘。
- 若 `T+1` 某证券无行情，订单拒绝，不顺延。

现有 V1a 日线只有日期而没有真实发布时间，因此适配层统一推定
`available_at = trade_date 15:30 Asia/Shanghai`，并输出
`availability_source = inferred_for_smoke_test`。该时间只用于验证系统边界，不能作为数据实际发布时效的证据。

预测周期为 `h` 时：

```text
forward_return_h[T] = open[T+h+1] / open[T+1] - 1
```

研究固定输出 1、5、10、20 日标签，5 日为主周期。任一端点无该证券行情时标签为空，
不得向前、向后填充或跳到该证券下一次交易日。

### 6.3 防泄漏不变量

- 任一 `T` 日股票池、因子、阈值和权重只能读取 `trade_date <= T` 且已发布的数据。
- 未来标签不能参与当日数据清洗、股票池、因子处理或组合生成。
- 截面缩尾和排名只使用同一 `T` 日的合格截面。
- 向数据尾部追加未来日期后，历史股票池、调整收益、因子和信号必须逐值不变。

## 7. 价格、复权和公司行为

V1a 使用现有原始价格做工程验收，并固定输出：

```text
price_basis = raw_unadjusted_smoke_test
corporate_actions_complete = false
```

V1b 同时保留两条价格语义：

- **执行价格**：交易当时真实的未复权价格。
- **研究总回报**：基于逐次公司行为事件构造，不得使用会因未来分红送转而改写过去的
  普通后复权快照。

分红进入现金，送转调整股份数量，配股单独建模。退市、收购和私有化必须有明确终值事件。
证券不得在最后一条行情后从持仓中凭空消失；V1b 缺少终值时正式回测失败。

## 8. 历史时点股票池

### 8.1 市场范围

V1a 允许按代码推断市场，但只用于 smoke test：

- 排除 `sh900xxx` 和 `sz200xxx` B 股。
- `sh688xxx`、`sh689xxx` 识别为科创板。
- `sz300xxx`、`sz301xxx` 识别为创业板。
- `bj` 前缀识别为北交所。
- 其余合格沪深证券按主板处理。

V1b 必须由带生效区间的 PIT 证券主表提供市场、板块和交易状态，代码推断不得作为权威来源。

### 8.2 准入条件

每个信号日 `T` 的证券必须同时满足：

1. `T` 日存在行情。
2. 上市已满 60 个市场交易日；V1a 缺少上市日时只能用可见历史长度近似并标记。
3. V1b 中当时不是 ST/*ST，且当日可交易。
4. 三个基线因子均非空。
5. 目标单股仓位不超过20日平均成交额的 1%。
6. 20日平均成交额不低于 2,000 万元。

流动性比例、绝对下限和目标资金均写入配置。不得使用全样本成交额分位数筛选历史股票池。

合格证券少于 100 只时不生成新信号，保留原持仓并记录
`INSUFFICIENT_UNIVERSE`。已有持仓后来变成 ST、停牌或不再准入时，必须通过真实可执行订单退出，
不能直接从账户删除。

V1a 固定输出：

```text
universe_pit_complete = false
```

## 9. 固定基线因子

三个因子的方向统一为“值越高，预期收益越高”。公式在锁定测试前不得按结果调参。

### 9.1 20-5 日动量

```text
momentum_20_5[T] = close[T-5] / close[T-20] - 1
```

### 9.2 5 日反转

```text
reversal_5[T] = -(close[T] / close[T-5] - 1)
```

### 9.3 20 日低波动

```text
low_volatility_20[T] = -sample_std(log_return, 20 market-day observations)
```

样本标准差使用 `ddof=1`。端点或窗口内必需行情缺失时因子为空，不按证券自身报价序列跳日。

### 9.4 截面处理与合成

在每个信号日合格截面内：

1. 按因子分别计算当日 1%/99% 分位点并缩尾。
2. 使用平均秩处理并列值，转为 `[−1, 1]` 百分位分数。
3. 三个因子完整时做简单算术平均。
4. 按综合分数降序、`symbol` 升序确定唯一顺序。

成交额只用于股票池过滤，不进入 Alpha 分数。

## 10. 因子研究与验证

每个原始因子和综合因子输出：

- 1、5、10、20 日逐期 Spearman RankIC。
- IC 均值、标准差、ICIR 和 Newey-West/HAC t 值。
- 五分层等权收益与 Top-minus-Bottom 诊断收益。
- 分层单调性、覆盖率、缺失率、极值和换手率。
- 前后区间、年度和市场阶段稳定性。
- 因子之间的逐期截面秩相关和衰减曲线。

周期为 `h` 日且按周采样时，HAC 滞后阶数以重叠的周度观测数确定：

```text
max_lags = max(0, ceil(h / 5) - 1)
```

V1 新增唯一统计依赖 `statsmodels`；不自行实现 Newey-West，也不新增 Polars、PyArrow或第三方回测框架。

### 10.1 时间划分

V1b 按时间顺序划分：

- 前 60%：开发集。
- 中间 20%：验证集。
- 最后 20%：锁定测试集。

因子方向、窗口、缩尾、合成权重和主周期必须在查看锁定测试集前冻结。查看测试结果后发生的任何修改，
都使该测试集失去 OOS 身份；后续必须使用新的未来数据作为测试集。

### 10.2 实验登记

每次研究前记录：假设、经济机制、方向、公式、参数、主周期、数据版本和淘汰条件。
失败实验也必须保留。扩展大量因子时必须加入多重检验/FDR 控制。

### 10.3 研究候选门槛

`RESEARCH_CANDIDATE` 至少要求：

1. 不少于 5 年历史和 200 个有效周度截面。
2. 覆盖至少两个明显不同的市场阶段。
3. 主周期 5 日 RankIC 的 HAC `|t| > 2` 且方向符合预注册假设。
4. 前后半段 RankIC 同号。
5. 衰减与周度调仓相容。
6. 与已接纳因子的平均截面秩相关绝对值小于 0.7。
7. 默认资金和成交约束下目标成交完成率不低于 95%。

当前数据无条件固定为 `SMOKE_TEST`。V1a 测试不得断言收益、IC 或 Sharpe 为正。

## 11. 价格型 Barra-lite 审计

V1 不声称实现完整 Barra。只审计 OHLCV 可支持的价格型风格：

- Beta：对同期 PIT 股票池等权日收益做含截距 OLS，使用过去120个市场交易日，
  至少100个成对有效观察。
- 动量：预注册的20-5日动量暴露。
- 残差波动率：上述120日 Beta 回归残差的样本标准差，至少100个有效残差。
- 流动性：过去20个市场交易日成交额均值的自然对数，20个观察必须完整。

输出组合原始暴露，并用同日截面回归报告控制这些可用风格后的残差 IC/收益诊断。
首版组合不做风格中性化或优化。

规模、非线性规模、价值、盈利、成长、杠杆和行业暴露统一输出 `UNAVAILABLE`，
不得使用当前市值或行业快照回填历史。Beta 窗口不足时也输出 `UNAVAILABLE`，不能缩短窗口迎合当前数据。

## 12. 组合与研究基准

### 12.1 策略组合

- 默认初始资金：人民币 1,000 万元，可配置。
- 每周生成 Top 50 等权目标，单股目标上限 2%。
- 只做多、不加杠杆、不允许负现金。
- 手数、现金、停牌和成交限制产生的余额保留为现金。
- 不加入排名缓冲、权重优化或根据当前结果选择参数。

### 12.2 研究基准

`pit_universe_equal_weight_gross` 是相同历史时点合格股票池的等权、5 日开盘到开盘毛收益。
它不模拟持有全市场的真实成交，不能称为可投资指数。

报告同时给出：

- 策略毛收益与基准毛收益之差。
- 策略净收益与基准毛收益之差。
- 交易成本对两者差异的贡献。

不能只报告“策略净收益减基准毛收益”而不拆分选股与实现成本。

## 13. V1a 执行器

执行器只支持单策略、单人民币现金账户。核心逻辑不得调用系统当前时间，所有时钟显式传入。

每个市场交易日按顺序：

1. 按 acquisition lot 解锁到期股份。
2. 在信号后的首个市场交易日按开盘时账户 NAV 生成调仓订单。
3. 先卖后买；卖出回款可用于当日后续买入。
4. 应用交易状态、价格限制、申报数量、历史流动性和现金检查。
5. 以开盘价加减滑点成交。
6. 逐笔结算费用并更新现金、lots 和持仓。
7. 用当日收盘价估值；停牌持仓使用最近可见收盘价并累计 `stale_days`。

### 13.1 有效期交易约束

V1a 可按代码和价格推断规则，但必须标记 `constraints_source = inferred`。
V1b 必须消费按日期生效的 `instrument_constraints`：

```text
trade_date, symbol, is_tradable, limit_up, limit_down,
min_buy_qty, qty_step, price_tick, source_version
```

执行器不得自行硬编码历史规则。

### 13.2 T+1 与申报数量

- 买入按 acquisition lot 保存数量、买入日和解锁日。
- 当日买入 lot 下一市场交易日才可卖出。
- 沪深主板和创业板：买入为100股整数倍。
- 科创板：至少200股，超过200股后按1股递增。
- 北交所：至少100股，超过100股后按1股递增。
- 零股余额卖出时一次性处理。

### 13.3 价格限制

V1a 推断规则：沪深主板10%、创业板/科创板20%、北交所30%，按0.01元价格单位计算。
开盘达到涨停价时保守拒绝买入，达到跌停价时保守拒绝卖出。

不能使用当日最高、最低或全日成交量判断开盘排队是否成交。历史 ST 和上市初期状态缺失意味着
V1a 不是完整规则复现。

### 13.4 流动性和订单生命周期

- 目标单股仓位原则上不超过截至 `T` 日20日平均成交额的1%。
- 执行硬上限为截至 `T` 日20日平均成交量的5%。
- 不得使用 `T+1` 全日成交量决定开盘成交数量。
- 允许部分成交，未成交余额当日取消，不跨日追单。
- 调仓日按最新目标重新生成订单。

这些约束是日线容量代理，不代表开盘盘口真实深度。

### 13.5 停牌与陈旧估值

停牌持仓可使用最后可见收盘价估值，但必须输出 `stale_days`。V1b 中若长期无行情且没有匹配的
证券状态或终值事件，运行失败；不能无限期以陈旧价格隐藏损失。

## 14. 成本与敏感性

费用必须按生效日期选择，不能把当前费率套用到全部历史。

V1a 当前区间默认：

| 项目 | 默认值 | 方向 | 性质 |
|---|---:|---|---|
| 券商佣金 | 3 bp，最低5元/订单/交易日 | 双向 | 账户假设 |
| 证券交易印花税 | 5 bp | 卖出 | 有效期规则 |
| A股过户费 | 0.1 bp | 双向 | 有效期规则 |
| 滑点 | 5 bp | 双向 | 基准模型 |

滑点另外运行10 bp和20 bp压力场景。不能用 T+1 当日振幅事后决定滑点。
部分成交若未来跨交易日，佣金最低额按每个订单在每个交易日的实际成交额分别结算。

- `https://one.sse.com.cn/onething/gptz/`
- `https://www.chinaclear.cn/zdjs/editor_file/20220701154723234.pdf`
- `https://www.mof.gov.cn/jrttts/202308/t20230828_3904235.htm`

## 16. 运行身份与产物

`run_id` 是配置、核心源码哈希和数据 manifest 哈希的内容哈希。相同输入必须得到相同
`run_id` 和逐值相同的结果。当前目录没有 Git 时，使用核心源码文件 SHA-256 代替代码提交号。

运行先写入临时目录，全部检查成功后原子提升到最终目录并创建 `_SUCCESS`。
没有 `_SUCCESS` 的目录不得被报告或下游任务消费。失败运行保留错误清单和日志，但不标记成功。

最终产物收缩为：

```text
artifacts/runs/<run_id>/
  config.json
  data_manifest.json
  research_panel.parquet
  orders.parquet
  fills.parquet
  positions.parquet
  nav.parquet
  metrics.json
  report.md
  figures/
    ic_series.png
    decay.png
    quantiles.png
    nav_drawdown.png
    style_exposure.png
  _SUCCESS
```

`research_panel` 合并股票池标记、因子、标签、风格暴露、排名、信号和目标权重。
订单、成交、持仓和 NAV 保持独立审计表。

绩效年化使用252个市场交易日；首版 Sharpe 使用零无风险利率并写入配置。

## 17. 为未来 Paper Trading 固定的数据契约

V1a 不实现 Broker 或 Paper Trading，只固定可重放、幂等的契约：

- `signal_id`、`order_id`、`client_order_id` 全局唯一。
- 目标权重、订单、成交、拒单、现金和持仓都有明确 `as_of` 时间。
- 重复提交同一 `client_order_id` 不得重复成交。
- 订单状态转换可从事件记录重放。
- 策略只输出目标权重，不依赖具体 Broker。

网络连接、调度、实时行情、账户同步、断线恢复和 RealBroker 在未来 Paper Trading 设计中单独处理。

## 18. 错误和警告边界

立即失败：

- schema、类型、主键或市场日期不符合契约。
- 官方应开市但全市场行情缺失。
- 追加未来数据后历史结果改变。
- 当前公司快照进入历史股票池。
- 目标权重为负、总权重超过100%或现金为负。
- 持仓、可卖数量、锁定数量为负。
- 成交超过订单量或历史容量上限。
- V1b 缺少公司行为、证券状态或退市终值。

记录并继续：

- 个别因子或标签缺失。
- 订单被市场约束拒绝或部分成交。
- 停牌持仓使用陈旧估值。
- V1a 无法识别 ST、上市初期和公司行为。
- 合格股票不足100只时跳过调仓。

## 19. 测试策略

### 19.1 单元测试

- 三个因子公式、窗口边界、NaN 和停牌端点。
- 截面缩尾、平均秩、并列值和确定性排序。
- 1/5/10/20 日市场日历标签。
- 市场映射、B 股排除和 V1a 约束推断。
- Top 50、最少100只、权重、手数和现金。
- 有效期费用、最低佣金和三档滑点。

### 19.2 防泄漏测试

- 追加未来行情后，历史股票池、调整收益、因子和信号逐值不变。
- 打乱未来标签不改变因子和目标权重。
- 历史股票池不能访问 `company_snapshot_current`。
- 开盘成交不能读取当日最高、最低和全日成交量。

### 19.3 执行与会计测试

- 停牌、涨停买入、跌停卖出和无行情拒单。
- acquisition lot 的 T+1 解锁。
- 主板/创业板、科创板和北交所申报数量。
- 容量上限、部分成交、现金不足和当日取消。
- 卖出回款后买入、公司行为和退市终值。
- 订单事件幂等重放。
- 每日验证：`现金 + 持仓市值 = NAV`。

### 19.4 集成与真实数据测试

- 人工构造的小型数据精确断言信号日、订单日、成交日、现金、持仓、费用和 NAV。
- 真实上游数据只验证全流程可运行、主键、不变量和 `SMOKE_TEST` 状态。
- 不把真实数据净值曲线作为 golden test，不断言收益、IC 或 Sharpe 为正。

## 20. V1a 完成标准

V1a 只有同时满足以下条件才完成：

1. 五个最小模块及入口按约定职责工作。
2. 当前真实数据完成端到端运行并标记 `SMOKE_TEST`。
3. 人工测试精确覆盖时间对齐、T+1、限制价、停牌、手数、费用、容量和账户恒等式。
4. 防泄漏测试证明追加未来数据不会改变历史结果。
5. 相同输入产生相同 `run_id` 和相同输出。
6. 成功运行具备 `_SUCCESS`，失败运行不能被误消费。
7. 报告明确列出数据、PIT、公司行为、复权和成交模型限制。

V1a 完成不代表 V1b 数据合格，也不代表任何因子或组合有效。
